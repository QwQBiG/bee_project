# 队伍 614689 可执行程序打包说明

本流程依据 2026 年 9 月《作品提交要求》附件4。最终结果是四个EXE共享
`_internal/`与`weights/`的PyInstaller onedir目录，以及不额外嵌套目录的
`EXE-614689.zip`。

## 1. 准备ONNX权重

开发环境仍可使用Python 3.13和本地Torch wheel。先安装ONNX导出依赖，然后导出：

```bat
py -3.13 -m pip install onnx onnxscript
py -3.13 tools\export_submission_onnx.py
```

必须得到：

```text
artifacts/models/hive_entrance_bee_yolov8n.onnx
artifacts/models/bee_inside_ft_v1.onnx
```

## 2. 建立独立打包环境

官方建议Python 3.10；这不是评测机依赖，只是生成自包含EXE的构建环境。
提交打包依赖已经锁定为CUDA 13.2 Update 2组件，不能把
`onnxruntime-gpu[cuda,cudnn]`直接加入命令，否则pip可能自动选到CUDA 13.3。

```bat
py -3.10 -m venv .venv-build
.venv-build\Scripts\python.exe -m pip install --upgrade pip
.venv-build\Scripts\python.exe -m pip install -r deployment\requirements-submission.txt
```

如使用已经配置好的Python 3.13环境，也可以把上面的Python路径换成对应解释器。
正式EXE的推理和跟踪不包含Python开发环境、Torch、Torchvision或Ultralytics；
它使用ONNX Runtime GPU和轻量两阶段跟踪器，`lap`已随onedir封装。

## 3. 生成初始程序目录与ZIP

```bat
.venv-build\Scripts\python.exe build_submission.py --team_id 614689 --runner deployment\competition_runner.py --weights artifacts\models
```

如果仍有未自动收集的DLL：

```bat
.venv-build\Scripts\python.exe build_submission.py --team_id 614689 --runner deployment\competition_runner.py --weights artifacts\models --runtime_dll_dir runtime_dlls
```

输出为`EXE-614689/`和初始`EXE-614689.zip`。

## 4. 单程序检查

```bat
.venv-build\Scripts\python.exe evaluation_call.py --exe "EXE-614689\Inside-detection-614689.exe" --input "demo_input\Inside\detection\images"
```

被测EXE必须返回操作系统退出码0，stdout只能包含一行状态JSON；运行日志只允许
出现在stderr。

## 5. 生成selfcheck

`demo_input`应替换为本队自建、四个任务均有连续JPG的测试目录：

```bat
.venv-build\Scripts\python.exe make_selfcheck.py --team_id 614689 --exe_dir EXE-614689 --selftest_root demo_input
```

## 6. 校验并重新压缩

```bat
.venv-build\Scripts\python.exe validate_package.py --team_id 614689 --exe_dir EXE-614689
.venv-build\Scripts\python.exe rezip_after_selfcheck.py --team_id 614689 --exe_dir EXE-614689
```

最终ZIP压缩后不得超过4GB，解压后不得超过8GB。ZIP根目录应直接包含四个EXE、
`_internal/`、`weights/`和`selfcheck/`。
