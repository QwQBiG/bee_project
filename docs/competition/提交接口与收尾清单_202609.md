# 比赛提交接口与收尾清单（2026-09）

本文依据组委会 2026 年 9 月发布的《作品提交要求》整理。旧版逐图
`--image_path` 接口仅供历史兼容，不得用于最终提测。

## 当前已经完成

- 文件夹级标准输入：`--input "<JPG 文件夹绝对路径>"`。
- 自动解析官方文件名中的 1-based `frame_id`，并检查必须从 1 到 N 连续。
- 检测和跟踪汇总 JSON 的固定字段、记录顺序、数量及数值范围校验。
- 检测结果按帧号升序、同帧置信度降序排列。
- 巢外每帧最多 200 框，巢内每帧最多 600 框。
- 跟踪结果按帧号、轨迹 ID 升序排列，`track_id` 不复用。
- JSON 使用 UTF-8 紧凑单行格式，拒绝 `NaN`、`Infinity` 等非法数值。
- 公共源码入口：`python -m inference.batch_cli`。

源码调试示例（`438137` 仅为格式示例，不代表正式队伍 ID）：

```powershell
python -m inference.batch_cli `
  --input "C:/Test/Inside/detection/images/" `
  --sequence Inside-detection `
  --team-id 438137 `
  --output-dir "C:/TestResults/"
```

正式 EXE 不传 `--sequence` 和 `--team-id`，程序从规定的 EXE 文件名解析：

- `Inside-detection-<队伍ID>.exe`
- `Inside-tracking-<队伍ID>.exe`
- `Outside-detection-<队伍ID>.exe`
- `Outside-tracking-<队伍ID>.exe`

## 最后阶段再完成

以下内容依赖最终队伍 ID、权重和环境，应在算法不再改动后一次完成：

1. 确定正式六位队伍 ID，并验证四个 EXE、四个 JSON 中完全一致。
2. 锁定巢内、巢外 ONNX 权重及跟踪阈值。
3. 生成四个规定名称的 EXE，并在断网 Windows 11 环境实测。
4. 检查每个程序仅接受 `--input` 即可运行，控制台仅有一行状态摘要。
5. 将结果写入 `C:/TestResults/`，逐个通过结构和数量校验。
6. 生成 `selfcheck/`，再制作 `EXE-<队伍ID>.zip`。
7. 最后组装六个固定一级目录及报名、签署材料。

## 当前算法边界

- 巢内外检测已有训练结果，但现有数字主要来自本地验证集，不能代替官方盲测。
- 巢外跟踪已有 VnBeeTracking 真值基线，当前主要瓶颈是检测召回率。
- 巢内缺少对应的个体身份真值，继续盲调跟踪参数无法证明收益。
- 姿态和行为量化可作为研究与展示材料，但未提供 OKS 参数和正式 POSE
  读取说明前，不应把 HBB 自动评测入口切换为 POSE。

因此，最终打包前最值得做的算法工作只有两类：使用真实留出真值复测模型，或
获得新的人工真值后训练。没有真值支持的复杂改造不进入正式分支。
