# 官方多目标跟踪器对照评测

## 评测目的

在保持蜜蜂检测权重、输入视频和设备不变的条件下，对照 Ultralytics 官方 ByteTrack 与 BoT-SORT。前面的无真值短片段只记录工程指标；第 5 节补充了与本地巢外视频对应的 VnBeeTracking 身份真值评测。

## 评测环境与命令

- 检测模型：现有巢外 `hive_entrance_bee_yolov8n.pt`、巢内 `honey_bee_detector_yolov8s.pt`
- 设备：自动选择的 CUDA GPU
- 跟踪后端：官方 `bytetrack.yaml`、`botsort.yaml`
- 评测脚本：`tools/compare_trackers.py`

```powershell
python tools/compare_trackers.py `
  --mode outside `
  --video data/external/vnbee/vnbee_outside_test_2s.mp4 `
  --config configs/demo_outside_test.yaml `
  --output output/tracker_compare/outside_30f.json `
  --frames 30
```

## 巢外 30 帧结果

| 跟踪器 | 平均检测数/帧 | 平均轨迹数/帧 | 最大轨迹数 | 观察到的 ID 数 | 处理速度 |
|---|---:|---:|---:|---:|---:|
| BoT-SORT | 6.63 | 6.50 | 12 | 18 | 3.07 FPS |
| ByteTrack | 6.33 | 6.33 | 12 | 18 | 15.21 FPS |

在当前无真值巢外短片段中，两者轨迹数量接近，ByteTrack 速度约为 BoT-SORT 的 5 倍。带真值的 120 帧结果见第 5 节：BoT-SORT 精度略优，ByteTrack 速度更快。

## 巢内红外 3 帧结果

| 跟踪器 | 平均检测数/帧 | 平均轨迹数/帧 | 最大轨迹数 | 观察到的 ID 数 | 处理速度 |
|---|---:|---:|---:|---:|---:|
| BoT-SORT | 186.33 | 186.33 | 203 | 209 | 0.265 FPS |
| ByteTrack | 185.67 | 185.67 | 203 | 209 | 0.675 FPS |

巢内红外样本中检测框数量明显偏高，且样本过短，不能据此判断身份精度。ByteTrack 在该片段上更快，暂作为巢内速度基线；巢外带真值结果显示 BoT-SORT 略优，因此巢外默认切换为 BoT-SORT。后续必须使用带身份标注的红外数据评测 HOTA、IDF1 和 ID Switch。

## 结论与限制

1. 两个后端均为真实论文算法实现，不再使用项目内自定义的伪 DeepSORT 或损坏的自定义 ByteTrack。
2. 无真值短片段中 ByteTrack 速度更快；带真值的巢外片段中 BoT-SORT 指标略优，因此当前巢外默认使用 BoT-SORT，巢内仍以 ByteTrack 作为速度基线。
3. BoT-SORT 的 ReID 默认关闭；若要体现其身份关联优势，需要蜜蜂身份标注和适配红外域的 ReID 模型。
4. 没有身份真值的片段不报告 MOTA、IDF1、HOTA；第 5 节仅对有公开 GroundTruth 的巢外片段报告 IoU=0.5 基线。

## 5. 带 VnBeeTracking 真值的 120 帧评测

本阶段首次使用与本地巢外视频对应的公开 GroundTruth 文件进行逐帧评测。标注格式为 `frame,id,x,y,w,h,1,1,1`，IoU 匹配阈值为 0.5。评测脚本为 `tools/evaluate_vnbee_tracking.py`，不需要额外安装 MOT 指标库。

| 指标 | ByteTrack | BoT-SORT |
|---|---:|---:|
| 原始检测 Precision | 0.554 | 0.557 |
| 原始检测 Recall | 0.194 | 0.202 |
| 原始检测 F1 | 0.288 | 0.296 |
| 跟踪 IDF1 | 0.270 | 0.287 |
| MOTA | 0.035 | 0.040 |
| ID Switch | 8 | 4 |
| 吞吐率 | 10.38 FPS | 8.38 FPS |

结果说明：BoT-SORT 在当前 120 帧巢外真值片段上的 Precision、Recall、F1、IDF1 和 ID Switch 均略优于 ByteTrack，但速度较低。两者的检测 Recall 都约为 0.20，说明当前主要瓶颈是蜜蜂检测漏检，而不是单纯的轨迹关联算法。

这些指标是 IoU=0.5 下的工程基线，不等同于完整 TrackEval HOTA。下一阶段应先在相同真值上调检测模型的置信度、输入尺寸和训练数据，再复测两个跟踪后端；巢内红外还需要下载并对齐 OIST 的检测/轨迹标注后才能进行同类评测。

复现实验命令：

```powershell
python tools/evaluate_vnbee_tracking.py `
  --video data/external/vnbee/vnbee_outside_test_2s.mp4 `
  --gt <VnBeeTracking GroundTruth\2022-04-08-12-30.txt> `
  --config configs/demo_outside_test.yaml `
  --output output/evaluation/vnbee_botsort_120.json `
  --frames 120 `
  --tracker botsort
```
