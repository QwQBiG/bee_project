# 正式数据划分与双标复核规范

## 1. 基本原则

同一原始视频及其裁剪片段、抽帧图片、增强版本必须属于同一个数据集合。禁止把同一视频的相邻帧随机分配到训练集和验证集，否则评测结果会因时间相邻画面高度相似而虚高。

数据划分单位为完整视频，视频 SHA-256 用于识别改名或复制后的同源文件。

## 2. 官方视频固定划分

当前划分种子为 `bee-competition-v1`。

### 训练集

- 巢内：`B-5-3.mp4`、`B-5-4.mp4`
- 巢外：`A-5-1.mp4`、`A-5-2.mp4`

### 验证集

- 巢内：`B-5-1.mp4`
- 巢外：`A-5-4.mp4`

### 最终测试集

- 巢内：`B-5-2.mp4`
- 巢外：`A-5-3.mp4`

最终测试集只能在模型结构、训练超参数、置信度阈值和后处理规则全部锁定后使用。测试结果不能再用于调整模型。

划分清单由以下命令生成：

```powershell
python tools/plan_grouped_split.py `
  datasets/official_work/official_full_manifest/dataset_manifest.json `
  datasets/official_work/official_split_plan `
  --seed bee-competition-v1
```

生成结果包括：

- `split_manifest.json`
- `split_audit.json`
- `train_videos.txt`
- `val_videos.txt`
- `test_videos.txt`

审计同时检查 `video_id`、SHA-256 和规范化源路径是否跨集合重复。

## 3. 当前首批任务的集合归属

- `outside_train_task` 来自 `A-5-1`，属于训练集。
- `inside_val_task` 来自 `B-5-1`，属于验证集。

验证集标注可以用于计算指标和选择模型，但不能参与梯度训练或训练集增强。首批十帧主要用于验证标注、训练和推理链路；正式模型需要继续标注训练集中的其他完整视频。

## 4. 双标注复核

关键点金标准建议采用以下流程：

1. 标注者甲独立完成整蜂框和三个关键点；
2. 标注者乙在看不到甲结果的情况下独立完成同一批帧；
3. 运行一致性检查生成裁决清单；
4. 第三人只复核存在分歧的帧；
5. 裁决完成后的版本才标记为人工金标准。

比较命令：

```powershell
python tools/compare_pose_annotations.py `
  reviewer_a.json `
  reviewer_b.json `
  agreement_report.json `
  --min-match-iou 0.30 `
  --max-keypoint-error 0.15 `
  --strict
```

检查项目包括：

- 两人检测数量是否一致；
- 整蜂框 IoU；
- `head`、`thorax`、`abdomen_tip` 的归一化距离；
- 关键点可见性是否一致；
- 是否发生头尾对调；
- 未匹配实例和需要第三人裁决的帧号。

`--strict` 模式下，只要仍有待裁决帧就返回非零退出码，适合作为训练前质量门禁。

## 5. 指标解释

双标注一致性报告是人工标注质量筛查，不是模型准确率。高密度画面使用检测框 IoU 贪心匹配，存在对应关系歧义时必须人工裁决，不能自动合并两份标注。

正式模型评测至少分别报告：

- 整蜂检测：Precision、Recall、mAP50、mAP50-95；
- 短时跟踪：HOTA、IDF1、ID Switch；
- 姿态关键点：PCK、OKS 或归一化关键点误差、头尾翻转率；
- 进出巢事件：事件级 Precision、Recall、F1 和计数误差；
- 巢内红外与巢外可见光的分场景结果。
