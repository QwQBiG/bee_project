# 关键点姿态模型接入说明

## 1. 当前能力边界

巢内检测模型负责识别整蜂，跟踪器负责生成短时轨迹 ID。整蜂检测框本身不能确定头部、胸部和腹部方向。

系统的关键点姿态模块默认关闭。关闭时：

- 不输出头部框或腹部框；
- 不根据检测框左右位置猜测头尾；
- 头尾方向指标标记为 `unknown`；
- 检测框形状异常只能作为 `candidate_only` 候选；
- 检测、跟踪、密度和画面内速度统计不受影响。

## 2. 姿态模型的输出定义

姿态模型使用一个 `bee` 类别，并按固定顺序输出三个关键点：

1. `head`：头部中心；
2. `thorax`：胸部中心；
3. `abdomen_tip`：腹部末端。

只有三个关键点全部存在且置信度达到阈值时，系统才会生成：

- 头部朝向角；
- 头、胸、腹端关键点；
- `head_tail_known=true`；
- `source=validated_pose_model`。

头部朝向角定义为从腹部末端指向头部的有向角，范围为 0～360 度。

## 3. 训练数据门禁

训练前必须满足以下条件：

- 标注来源已经人工复核；
- 每个有效蜜蜂实例具有完整的三个关键点；
- 训练集和验证集均非空；
- `dataset_meta.json` 中 `pose_labels_ready=true`；
- `dataset_meta.json` 中 `training_ready=true`。

自动预标注、插值结果或只有整蜂框的数据不能直接作为姿态训练真值。

验证命令示例：

```powershell
python tools/validate_annotations.py --input <回导后的标注.json> --gold --pose-gold
```

训练前检查示例：

```powershell
python main.py --mode train `
  --task pose `
  --model yolov8s-pose.pt `
  --data <姿态数据集>/data.yaml `
  --output artifacts/training `
  --dry_run
```

检查通过后删除 `--dry_run` 启动正式训练。

## 4. 推理配置

在巢内配置文件中增加：

```yaml
pose_model:
  enabled: true
  model_path: "artifacts/models/bee_pose_best.pt"
  confidence: 0.25
  keypoint_confidence: 0.35
  min_track_iou: 0.30
  imgsz: 640
  device: null
```

参数说明：

- `enabled`：是否启用关键点推理；
- `model_path`：训练完成的 YOLO Pose 权重；
- `confidence`：姿态检测框最低置信度；
- `keypoint_confidence`：单个关键点最低置信度；
- `min_track_iou`：姿态检测与整蜂轨迹匹配的最低 IoU；
- `imgsz`：姿态推理图像尺寸；
- `device`：为空时按 CUDA、MPS、CPU 顺序自动选择。

模型文件不存在或不是 YOLO Pose 任务时，程序会直接报错，不会静默退回伪造关键点。

## 5. 结果字段

`inside_stats.json` 中的 `pose_model` 字段包含：

- `enabled`：本次是否启用姿态模型；
- `head_tail_supported`：本次是否具备头尾推理能力；
- `matched_track_observations`：成功匹配到轨迹的姿态观测数；
- `rejected_pose_detections`：因 IoU 或关键点条件不合格而拒绝的姿态结果数；
- `source`：姿态结果来源；
- `limitations`：当前结果的使用限制。

## 6. 正式评测要求

姿态模型不能只展示预测图片。正式报告至少需要基于独立人工真值集给出：

- PCK；
- OKS 或关键点平均误差；
- 头尾翻转率；
- 三个关键点分别的可见与遮挡性能；
- 巢内红外和巢外可见光的分场景结果。

进出巢方向仍由轨迹穿越人工标定的巢门区域判断。关键点头部朝向可以作为辅助证据，但不能代替完整的跨区轨迹。
